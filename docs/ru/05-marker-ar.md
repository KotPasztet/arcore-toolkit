# Маркерный AR

Когда устройство не трекает вообще (нет рабочего VIO или ARCore отказывается
работать), трекинг заменяется печатным маркером. Две части:

* **MarkerActivity** в тестовом приложении — самостоятельный прототип на Camera2 +
  OpenCV;
* **шим** — подменяет C-библиотеку ARCore внутри существующего приложения и
  подсовывает ему позы AprilTag (см. [06-shim.md](06-shim.md)).

## 1. Маркер

Рекомендуется **гибридный лист A3** — один большой маркер для дальности и четыре
маленьких для точности, разрешения неоднозначности PnP и устойчивости к
перекрытию.

```bash
python3 tools/calib/make_bundle.py
# bundle_a3_hybrid.pdf — A3 landscape, AprilTag 36h11
#   ID 0: 110 мм в центре
#   ID 1..4: 55 мм в (+/-150, +/-104) мм
# bundle_a3_hybrid_tags.txt — раскладка для шима
```

Эта раскладка встроена в шим. Чтобы переопределить её (или использовать свой
лист), положите манифест в папку данных приложения:

```bash
adb push tools/calib/bundle_a3_hybrid_tags.txt \
  /sdcard/Android/data/<pkg>/files/tags
```

Формат `tags` (миллиметры, система листа: X вправо, Y вниз, yaw вокруг Z):

```
# id x_mm y_mm yaw_deg size_mm
0 0 0 0 110
1 -150 -104 0 55
...
```

Шим детектит все ID из раскладки, переводит позу каждого маркера в систему листа и
взвешенно усредняет согласованные позы (по площади, `decision_margin` и ошибке
репроекции). Один ошибочный/неоднозначный маркер не утащит результат за собой.

Один большой маркер тоже поддерживается:

```bash
python3 tools/calib/make_marker.py
# marker_a4_150mm.pdf — ID 0, чёрный квадрат 150 мм
# файл tags: 0 0 0 0 150
```

Практика:

* матовая бумага, лазерная или струйная печать, без глянца (блики убивают детекцию);
* наклейте на жёсткую основу — изогнутый лист меняет позу;
* печатайте в масштабе 100% / actual size; измерьте линейку 100 мм;
* если печать масштабирована (например 99%), масштабируйте **и размеры, и
  координаты** в `tags` на `measured/100`;
* белые поля/quiet zone каждого маркера не должны перекрываться другими маркерами
  или объектами;
* центральный маркер 110 мм работает до ~2 м, угловые 55 мм — лучше всего до ~1 м.

## 2. Прототип (без ARCore)

`MarkerActivity`:

* Camera2 `YUV_420_888`, 640×480, `ImageReader` на 4 буфера;
* YUV → ARGB → `Bitmap` для превью (превью, детекция и оверлей в одной системе
  координат);
* OpenCV `ArucoDetector` с `DICT_APRILTAG_36h11`, `solvePnP` по 4 углам;
* куб на маркере, плюс ошибка репроекции и дистанция.

Кадр камеры поворачивается на **90° по часовой** для портрета (сенсор landscape).
Это эталон для обработки ориентации экрана в шиме.

Ожидаемые числа: ошибка репроекции 0.3–1 px на 0.3–0.7 м.

## 3. Системы координат

Поза AprilTag (`estimate_tag_pose`) в конвенции OpenCV:

* X вправо, Y вниз по изображению маркера;
* **Z от камеры**, то есть в поверхность, на которой напечатан маркер.

Для маркера, лежащего лицом вверх на столе, «вверх от стола» — это **−Z**. ARCore и
игры считают верхом **+Y**, поэтому шим пере-базирует мир:

```
x' = x,   y' = -z,   z' = y
```

## 4. Размер маркера и точность

| Дистанция | Маркер 150 мм | Маркер 300 мм |
|---|---|---|
| 0.3 м | отлично | избыточно |
| 0.5 м | хорошо | отлично |
| 1.0 м | рабочее (~50 px) | хорошо |
| 2.0 м | на грани | рабочее |

Точность позиции примерно `0.3 × distance² / (f × tag_size)`; на 0.5 м с маркером
150 мм — несколько миллиметров.

В гибридном листе центральный маркер 110 мм — дальний якорь; четыре угловых 55 мм
доминируют в усреднённой позе на 0.3–0.8 м и сохраняют трекинг, если один-два
угла перекрыты.

## 5. Советы

* Отбраковывайте детекции по `decision_margin`, `hamming` и площади: смазанный
  маркер «детектится» с неверной позой.
* Сглаживайте позу (One Euro) — шум одного кадра виден как дрожание контента.
* У плоского маркера **два допустимых решения PnP**. Проверяйте оба и берите
  ближайшее к предыдущей/предсказанной позе, иначе маркер «переворачивается» на
  ±15° при взгляде почти вдоль плоскости. Гибридный лист помогает: остальные
  маркеры отбрасывают неверное решение при усреднении в системе листа.
* Детекцию запускайте в отдельном потоке и всегда берите самый новый кадр. 10–20 Гц
  мало для рендера 60 fps, но заблокированный поток рендера ещё хуже: старые кадры
  выбрасывайте, а между детекциями предсказывайте позу.
* Держите выдержку короткой: смаз вредит точности сильнее шума.

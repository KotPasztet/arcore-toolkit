# Маркерный AR

Когда устройство не трекает вообще (нет рабочего VIO или ARCore отказывается
работать), трекинг заменяется печатным маркером. Две части:

* **MarkerActivity** в тестовом приложении — самостоятельный прототип на Camera2 +
  OpenCV;
* **шим** — подменяет C-библиотеку ARCore внутри существующего приложения и
  подсовывает ему позы AprilTag (см. [06-shim.md](06-shim.md)).

## 1. Маркер

```bash
python3 tools/calib/make_marker.py
# marker_a4_150mm.pdf — AprilTag 36h11, ID 0, внешний чёрный квадрат 150 мм
```

Практика:

* матовая бумага, лазерная или струйная печать, без глянца (блики убивают детекцию);
* наклейте на жёсткую основу — изогнутый лист меняет позу;
* измерьте напечатанный чёрный квадрат и используйте реальный размер: на листе есть
  линейка 100 мм; если она 99 мм, ставьте размер маркера `0.150 × 0.99 = 0.1485 м`;
* чем больше, тем лучше: 150–300 мм покрывают дистанции 0.3–2 м;
* маркер должен быть целиком в кадре (белая рамка важна).

## 2. Прототип (без ARCore)

`MarkerActivity`:

* Camera2 `YUV_420_888`, 640×480, `ImageReader` на 4 буфера;
* YUV → ARGB → `Bitmap` для превью (превью, детекция и оверлей в одной системе
  координат);
* OpenCV `ArucoDetector` с `DICT_APRILTAG_36h11`, `solvePnP` по 4 углам;
* куб на маркере, плюс ошибка репроекции и дистанция.

Кадр камеры поворачивается на **90° по часовой** для портрета (сенсор landscape).
Это эталон для обработки ориентации экрана в шиме.

Ожидаемые числа: ошибка репроекции 0.3–1 px на 0.3–0.7 м.

## 3. Системы координат

Поза AprilTag (`estimate_tag_pose`) в конвенции OpenCV:

* X вправо, Y вниз по изображению маркера;
* **Z от камеры**, то есть в поверхность, на которой напечатан маркер.

Для маркера, лежащего лицом вверх на столе, «вверх от стола» — это **−Z**. ARCore и
игры считают верхом **+Y**, поэтому шим пере-базирует мир:

```
x' = x,   y' = -z,   z' = y
```

## 4. Размер маркера и точность

| Дистанция | Маркер 150 мм | Маркер 300 мм |
|---|---|---|
| 0.3 м | отлично | избыточно |
| 0.5 м | хорошо | отлично |
| 1.0 м | рабочее (~50 px) | хорошо |
| 2.0 м | на грани | рабочее |

Точность позиции примерно `0.3 × distance² / (f × tag_size)`; на 0.5 м с маркером
150 мм — несколько миллиметров.

## 5. Советы

* Отбраковывайте детекции по `decision_margin` и `hamming == 0`: смазанный маркер
  «детектится» с неверной позой.
* Сглаживайте позу (One Euro) — шум одного кадра виден как дрожание контента.
* Для плавного движения ведите углы маркера оптическим потоком между детекциями:
  10–20 Гц недостаточно для рендера 60 fps.
* Держите выдержку короткой: смаз вредит точности сильнее шума.
